## 一、P0 — 止血

### [x] ORD-01 后台代付补建支付单

- **文件**：`app/Filament/Actions/Mall/OrderPaymentAction.php`
- **做法**：改为在事务内先 `PaymentOrder::create()`（`gateway=balance`、`paymentable=订单`），再调用 `PaymentService::payByBalance()`，由它完成密码校验、扣款、金额回写与订单推进
- **效果**：代付订单现在一定存在 `status=paid` 的支付单，售后链路可以取到资金单据

### [x] ORD-02 引入「已发数量」（`shipped_qty`）

- **文件**：`database/migrations/0003_02_00_000001_create_orders_table.php`（`order_items.shipped_qty`）、`OrderItem`、`Deliver`、`CancelDeliver`、`DeleteExpress`、`OrderShipAction`
- **做法**：`order_items` 增 `shipped_qty` 并回填历史行；可发数量 = `qty - 已退 - 已发`；发货按可发数量累加而不是整行绑定；完成判定改为「已发 + 已退 ≥ 购买数量」
- **兼容**：`resolveShippedQty()` 对「已绑定发货记录但 `shipped_qty=0`」的历史行按整行已发处理

### [x] ORD-03 后台删除统一走 `OrderService`

- **文件**：`Tenant/.../Orders/Tables/OrdersTable.php`、`Pages/ViewOrder.php`
- **做法**：`DeleteAction`/`DeleteBulkAction` 改为调用 `OrderService::delete()`；移除 `ForceDeleteBulkAction`；可见性补 `OrderStatus::deletable()` + `userCan('delete')`

### [x] ORD-04 修复两面板 `OrderInfolist` 的 `Order` 导入

- **文件**：两个 `OrderInfolist.php`
- **做法**：补 `use App\Models\Mall\Order;`

## 二、P1 — 用户可见缺陷

### [x] ORD-05 购物车下单强制邮寄地址

- **做法**：`address_id` 增加 `Rule::requiredIf(Mail)`；服务层对 `Mail` 断言地址非空（双保险）

### [x] ORD-06 禁止「部分发货直接签收」

- **文件**：`OrderStatus`（`next()`）、`OrderPolicy::orderSign`
- **做法**：删除 `PartiallyShipped → Signed` 边，`previous(Signed)` 同步收敛；签收按钮只对 `Delivered` 可见

### [x] ORD-07 支付通知移出事务

- **文件**：`Pay.php`
- **做法**：新增 `notifyTenant()`，用 `DB::afterCommit()` 包裹并 `try/catch + report()`；`tenant` 为空直接跳过

### [x] ORD-08 库存扣减/回补改用快照

- **文件**：`database/migrations/0003_02_00_000001_create_orders_table.php`（`order_items.deduct_stock_type`）、`OrderItem::resolveOrderable()`、`Pay`、`ReleasesOrderResources`、`CreateOrder`
- **做法**：`order_items` 快照 `deduct_stock_type`；扣减/回补按快照判断；商品软删时用 `withTrashed()` 回退查询，不再静默跳过

### [x] ORD-09 核销页准入改为非实例策略

- **文件**：`PickupVerify::canAccess()`
- **做法**：页面准入改用 `userCan('viewAny', Order::class)`；核销按钮仍由需要实例的 `orderVerify` 控制
- **效果**：非系统角色打开核销页不再 `TypeError`

### [x] ORD-10 订单明细空安全

- **文件**：`OrderItemResource::formatOrderable()`、`CreateRefundAction`
- **做法**：统一 `$orderable?->`，回退 `orderable_name` / `orderable_type` 快照

### [x] ORD-11 改运费联动待支付支付单

- **文件**：`UpdateFreight.php`、`PaymentController::payWechat()`
- **做法**：改运费后把该订单 `Pending` 的 `PaymentOrder.amount` 更新为新应付金额；微信下单前复核支付单金额与订单应付一致，不一致直接提示刷新

### [x] ORD-12 删除口径收敛
