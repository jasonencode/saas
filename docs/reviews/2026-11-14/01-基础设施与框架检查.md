# 基础设施与框架 检查报告

- **检查日期**：2026-11-14
- **检查范围**：`bootstrap/app.php`、`app/Providers/**`、`app/Http/Middleware/**`、`app/Http/Handlers/**`、`app/Http/Responses/**`、`app/Support/**`、`app/Console/**`、`routes/**`、`config/**`
- **检查方式**：逐文件走读 + 路由/中间件挂载点 grep + 定时任务与异常处理链路推演
- **结论**：本轮有真实修复——`PDOException/QueryException` 已按 500 分流、`ApiRecord` 已实现递归脱敏、租户实名资源补齐显式作用域、租户令牌已设 2 小时有效期。但**短信默认走 debug 网关（固定验证码）且发送接口读错字段**；多个安全中间件（`store.opened`、`BlackIpList`、`ApiRecord`、`AccessTokenAuthenticate`）只注册未挂载；`RuntimeException → 400` 仍未收敛，AES 仍无完整性保护。

**统计：严重 1 / 高 7 / 中 6（共 14 条）。**

---

## 一、严重问题

### INF-01 ｜ 严重 ｜ 短信 / 认证

**短信链路默认使用 debug 网关（固定 `0000`），发送接口读错字段**

- **位置**：`config/easy-sms.php:11,36-39,49`、`app/Services/Foundation/SmsService.php:91-93`、`app/Http/Controllers/Auth/SmsController.php:23`、`app/Http/Requests/Auth/SmsSendRequest.php:18`
- **代码要点**：`'debug' => env('EASY_SMS_DEBUG', true)`，网关顺序 `['debug','aliyun']`，`generateCode()` 直接返回配置中的 `0000`；`SmsController` 读 `phone`，请求只校验 `mobile`。
- **失败场景**：按 `.env.example` 部署时验证码恒为 `0000`；`/auth/sms` 实际传入空手机号，返回 204「成功」但无短信落库。
- **修复建议**：默认 `false`、生产强制非 debug；统一字段为 `mobile`；补「debug=false 不使用 debug 网关」与字段一致性测试。

## 二、高优先级问题

### INF-02 ｜ 高 ｜ 网络信任

**全局信任任意代理，IP 限流/黑名单/登录记录可被伪造头绕过**

- **位置**：`bootstrap/app.php:33`
- **失败场景**：`trustProxies(at: '*')` 任何客户端可伪造 `X-Forwarded-For`，`throttle:login/sms/register`、IP 黑名单、`LoginRecord`、支付回调 IP 全部失真。
- **修复建议**：改为实际反代网段（`config('custom.trusted_proxies')`）。

### INF-03 ｜ 高 ｜ 隐私 / 资源

**公开 `/sse` 泄露全站评论，且响应头拼写错误、无租户/审核/限流**

- **位置**：`routes/web.php:13`、`app/Http/Controllers/System/SseController.php:35-37,70-71`
- **失败场景**：匿名可拉取所有租户、所有审核状态的评论正文（`last_id=0` 全量）；每 0.8s 全表轮询、最长 120s，可占满 worker；头写成 `Contents-Type`，浏览器实际不进入 EventSource。
- **修复建议**：`auth:sanctum` + 租户/审核过滤 + `limit`；修正 `Content-Type`；改用广播/队列。

### INF-04 ｜ 高 ｜ 越权 / fail-open

**`checkPermission` 对 `user` 关联为 null 的模型直接放行**

- **位置**：`app/Http/Controllers/Traits/AuthorizesModelAccess.php:22`
- **失败场景**：订单、支付单、地址、退款等只要 `user` 为 null（硬删、脏数据），任意登录用户即可读取/操作。
- **修复建议**：`!$model->user` 时抛 404/403。

### INF-05 ｜ 高 ｜ 异常分层

**业务异常分流不完整：任意 `RuntimeException` 仍返回 400 + 原始 message**

- **位置**：`app/Http/Handlers/ApiExceptionHandler.php:47-48,108-113`
- **失败场景**：第三方库/文件系统/缓存/AES 的 `RuntimeException` 被当成客户端参数错误返回 400，客户端不重试、监控无 5xx，并泄露内部细节。
- **修复建议**：引入 `BusinessException` 白名单，仅它映射 400；其余 `RuntimeException` 走 500 + `report()`。

### INF-06 ｜ 高 ｜ 加密

**AES-256-CBC 无完整性校验，PII 密文可被位翻转/篡改**

- **位置**：`app/Support/AES/AES.php:13,78-90`
- **修复建议**：改 AES-256-GCM 存 tag，或 encrypt-then-MAC（HMAC-SHA256）。

### INF-07 ｜ 高 ｜ 业务开关

**`EnsureStoreIsOpened` 仅注册别名，从未挂载任何路由**

- **位置**：`bootstrap/app.php:36`、`app/Http/Middleware/EnsureStoreIsOpened.php:29-36`
- **失败场景**：未开通/已关闭商城的租户，商品、下单、支付接口仍完全可用。
- **修复建议**：在商城业务路由组统一挂载，或改服务层强制校验，并补 403 测试。

### INF-08 ｜ 高 ｜ 令牌生命周期

**访问令牌无过期：后台开弹窗即签发永久 Token，API 登录 Token 也永不过期**

- **位置**：`app/Filament/Actions/User/GenerateTokenAction.php:28`、`config/sanctum.php:53`、`app/Http/Responses/AuthResponse.php:33`
- **失败场景**：打开弹窗即落库无过期令牌，取消不回收、无审计；用户 token 泄露后永久有效。
- **修复建议**：显式提交后签发并设置 `expiresAt`/最小 abilities、写 `event_logs`；`sanctum.expiration` 配合理值。

## 三、中优先级问题

### INF-09 ｜ 中 ｜ Horizon 授权

**Horizon 授权对空用户解引用，且 local 环境直接放行**

- **位置**：`app/Providers/HorizonServiceProvider.php:32,48`
- **失败场景**：未登录访问 `/backend/horizon` 时 `$user` 为 null → `isAdministrator()` 抛 Error 500；local 环境任何人可进 Horizon 查看队列 payload。
- **修复建议**：`$user?->isAdministrator() ?? false`；local 放行改显式开关并记录日志。

### INF-10 ｜ 中 ｜ 上传

**上传无大小上限，且 Livewire 临时上传落在 public 磁盘**

- **位置**：`app/Http/Requests/UploadRequest.php:23-24`、`UploadsRequest.php:21-22`、`config/livewire.php:132`、`.env.example:61`
- **失败场景**：`max:` 仍被注释；默认磁盘为 `public`，实名证件在落私有盘前短暂落在可 Web 访问的 `livewire-tmp`。
- **修复建议**：恢复 `max:5120`；`LIVEWIRE_TEMPORARY_FILE_UPLOAD_DISK=local`。

### INF-11 ｜ 中 ｜ 后台安全

**「清缓存」Livewire 组件无任何权限校验**

- **位置**：`app/Livewire/Filament/ClearCache.php:14-15`
- **失败场景**：任何能进 backend 的账号都能清空生产缓存，造成缓存击穿；`modelCache:clear` 未安装时抛异常。
- **修复建议**：`userCan()`/策略限制 + 二次确认 + 审计；调用前检查命令存在。

### INF-12 ｜ 中 ｜ 黑名单

**IP 黑名单中间件未启用，实现本身也错误；IPv6 CIDR 会让检查崩溃**

- **位置**：`bootstrap/app.php:44`、`app/Http/Middleware/BlackIpList.php:25-29`、`app/Rules/IpOrCidr.php:68-70`、`app/Services/System/BlackListService.php:140-142`
- **失败场景**：中间件被注释 → 黑名单无效；若启用则「先执行业务后拒绝」，异常为 500；一条 IPv6 CIDR 会让所有请求检查失败。
- **修复建议**：`$next` 前判断并返回 403；`IpOrCidr` 限定 IPv4 或补齐 IPv6。

### INF-13 ｜ 中 ｜ 死代码

**`ApiRecord` 已脱敏但从未挂载，API 日志整体未生效**

- **位置**：`bootstrap/app.php:43-46`、`app/Http/Middleware/ApiRecord.php:48-75`、`tests/Feature/System/ApiRecordMaskingTest.php`
- **修复建议**：明确删除或正式挂载（补采样、异步写入、排除健康检查/上传下载）。

### INF-14 ｜ 中 ｜ 定时任务

**`chunk()` 边改状态导致跳过订单，且失败仍返回 SUCCESS**

- **位置**：`app/Console/Commands/Mall/OrderAutoCompleteCommand.php:48,92-103`、`PickupTimeoutCommand.php:65`、`OrderAutoSignCommand.php:62`、`IdentityExpireCommand.php:50`、`ReconcilePaymentRefundsCommand.php:64`
- **失败场景**：`chunk()` 按 OFFSET 分页，循环中把订单移出查询集会永久跳过约半数；失败仍 `return SUCCESS`，告警不触发。
- **修复建议**：改 `chunkById`（或先取 ID 快照）；失败返回 `FAILURE`/`warning`。
